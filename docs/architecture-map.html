ใช้ LM Studio สำหรับห้องเรียน

log ของ Ollama ระบุว่า “model architecture does not currently support parallel requests” (architecture=qwen35) จึงบังคับ -np 1 ตอบทีละคน ไม่ว่าจะตั้ง OLLAMA_NUM_PARALLEL เท่าไร LM Studio รัน Qwen 3.5 4B แบบขนาน 4 ช่องได้ เร็วกว่า 2.7 เท่า ไม่มีคำขอไหนเกิน timeout 90 วินาทีของแอปในทุกการทดสอบ

ผ่าน pipeline chat จริงของแอปบน LM Studio 20 คนพร้อมกัน: โมเดลตอบเอง 20/20 ไม่ถูก guardrail แทนที่ หลังเพิ่มกฎ “ต้องลงท้ายด้วย ?” ใน prompt chat (ก่อนเพิ่ม 25–50% ของคำตอบ chat เป็นประโยคบอกเล่า)

สิ่งที่แก้ใน LocalProvider

  • ส่ง reasoning_effort: "none" เป็นค่าเริ่มต้น (ปิดได้ด้วย LOCAL_LLM_REASONING_EFFORT=off)
  • JSON mode ใช้ json_schema ที่ทั้งสอง runtime รับ
  • timeout 90 วินาที แล้ว fallback
  • เลิกดึง reasoning_content มาแสดง เพราะเป็นความคิดภายในของโมเดล ไม่ควรถึงมือนักเรียน
  • prompt บังคับให้ลงท้ายด้วย ? เพราะเดิม Qwen ตอบเป็นประโยคสั่ง (“ลองเชื่อมโยง…”) แล้วโดน guardrail แทนที่ทุกครั้ง

ยังไม่ได้ทดสอบ

  • การใช้งานต่อเนื่องทั้งคาบ 50 นาที (ทดสอบแล้วแค่ burst 30 คนครั้งเดียว)
  • ชุด coach-evaluation เต็มชุด (docs/COACH_EVALUATION.md) กับ Qwen
  • คำชมแบบตัดสิน เช่น “เยี่ยมเลย คุณเข้าใจดีมาก” ที่ chat ยังพูดอยู่

ตัวอย่างข้อความผู้ปกครอง

Learning OS · รายงานสัปดาห์นี้ น้องทำกิจกรรม “สายใยอาหาร” ครบ 7 ขั้น และปรับปรุงข้อโต้แย้งหลังได้ feedback จากเพื่อน 2 ข้อ ชวนคุยที่บ้าน: “ถ้างูในทุ่งนาหายไป จะเกิดอะไรกับข้าว?”

ความปลอดภัยและกติกา

  • Channel secret และ access token อยู่ใน env ฝั่งเซิร์ฟเวอร์เท่านั้น
  • ทุก webhook ตรวจลายเซ็นก่อนอ่าน body · ตอบ 200 เร็ว แล้วทำงานต่อใน outbox
  • ใช้ X-Line-Retry-Key กันส่งซ้ำ
  • ยกเลิกผูกบัญชีได้ทันทีจากทั้ง LINE และหน้าเว็บ
  • โควตาข้อความฟรีของ OA มีจำกัดต่อเดือน ตรวจแพ็กเกจปัจจุบันของ LINE ประเทศไทยก่อนเปิดกับผู้ปกครองทั้งห้อง และรวมข้อความเป็นรายสัปดาห์เพื่อประหยัด
